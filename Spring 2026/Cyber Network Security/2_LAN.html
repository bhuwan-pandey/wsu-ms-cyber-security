Local Area Network and Switches

By Dr. Junjie Zhang

1. Local Area Network (LAN)

A Local Area Network (LAN) is the smallest type of computer network.
It connects a few devices (called nodes) within a small area such as a home, office, or classroom.

What Makes Up a LAN?

  • Nodes: Computers, laptops, printers, or servers.
  • Network Device: Usually a switch (or a hub, though switches are preferred).
  • Connections: Cables (Ethernet) or wireless (Wi-Fi).

The switch acts like the central meeting point. Each node connects to the switch, and the switch allows them to talk to each other.

A simple example:

  • PC A and PC B are connected to a switch.
  • The switch forwards data between them.
  • Together, this setup is a LAN.

2. Devices in a Network: Each Node Has an IP and a MAC

Every device connected to a network (PC, printer, server, router) is called a node.
Each node has at least two important identifiers:

  • MAC Address (hardware address)

    • Burned into the device’s network interface card (NIC).
    • Used by switches inside a LAN to deliver frames.
    • Example: AA:BB:CC:DD:EE:FF

  • IP Address (logical address)

    • Assigned to identify the device across networks.
    • Example: 192.168.1.10

We typically do not configure MAC addresses since they are pre-assigned by the manufacturer.
However, IP addresses in a LAN carry structural information. Specifically, all devices in the same LAN share the same network prefix, and the network mask (subnet mask) helps each device determine what part of its IP address represents the network portion.

Example

  • Device A: 192.168.1.10
  • Device B: 192.168.1.20
  • Netmask: 255.255.255.0 (binary: 11111111.11111111.11111111.00000000)

Applying the netmask to the IP address of Device A:

192.168.1.10   → 11000000.10101000.00000001.00001010
255.255.255.0  → 11111111.11111111.11111111.00000000
---------------------------------------------------
Network Prefix → 11000000.10101000.00000001.00000000 = 192.168.1.0

Doing the same for Device B produces the same result.
Thus, both devices compute the same network prefix (192.168.1.0) and know they are part of the same LAN.

Each node in the LAN, in addition to its MAC address and IP address, is also associated with a subnet mask that defines the boundaries of the network. A node can use its IP and the subnet mask to derive the network prefix of the LAN it belongs to.

From this output we can see:

  • MAC Address: 14:ac:60:2e:2a:75
  • IPv4 Address: 10.17.174.91
  • Netmask: 255.255.0.0
    • The netmask can also be expressed in CIDR notation (slash format):
      • 255.255.0.0 → /16
      • /16 means the first 16 bits represent the network portion, and the remaining bits represent the host portion.

A LAN is typically represented by its network prefix.

  • For this device, the network is represented as:
    • 10.17.0.0/16
  • This means all devices with addresses starting with 10.17.*.* (and using the same subnet mask /16) belong to the same LAN.

Practical Examples of Describing LANs with Network Prefixes

When IT people describe a LAN, they usually say something like “this network is 192.168.1.0/24” or “our subnet is 10.0.0.0/16”. That’s shorthand for:

  • All devices share that network prefix.
  • The subnet mask determines how many addresses are available for hosts.

Here are some conversational-style examples of how IT staff often describe LANs using network prefixes.

  1. Office Network Example

“Our office LAN is on 192.168.1.0/24."

That means everyone’s computer gets an address like 192.168.1.x, and the router is usually 192.168.1.1.

  1. University Lab Example

“The engineering lab runs on 10.0.0.0/16."

So all lab machines are in the range 10.0.x.x. If you’re outside that range, you’re not on the lab’s LAN.”

  1. Home Wi-Fi Example

“At home, my Wi-Fi uses 192.168.0.0/24. My laptop is 192.168.0.12, my phone is 192.168.0.15, and the printer is 192.168.0.20."

They’re all in the same LAN because they share the 192.168.0 prefix.”

  1. Data Center Example

“The servers in rack 5 are in 172.16.32.0/20."

That block gives us about 4,000 IPs, so we can host a lot of virtual machines in that LAN.”

3. Switch as a Table: Linking MAC Addresses to Ports

A switch is the central device that connects all the nodes in a LAN.
It works like a lookup table (called the MAC Address Table or Forwarding Table) that maps:

  • MAC Address → Active Port Number

This allows the switch to forward incoming frames only to the correct destination port instead of flooding the entire network.

Example:

MAC Address Port Number
AA:BB:CC:DD:EE:01 Port 1
AA:BB:CC:DD:EE:02 Port 2
AA:BB:CC:DD:EE:03 Port 3

When a frame destined for AA:BB:CC:DD:EE:02 arrives, the switch sends it only out of Port 2.

4. How the Switch Builds Its Table

Switches build their MAC address table gradually using a process called learning:

  1. Frame Arrival

    • A device (say PC A) sends a frame.
    • The switch reads the source MAC address and records it along with the incoming port.

  2. Table Update

    • If PC A’s MAC is AA:AA:AA:AA:AA:AA and it came from Port 1, the switch adds:
      • AA:AA:AA:AA:AA:AA → Port 1

  3. Forwarding Decision

    • When the switch receives a frame, it checks the destination MAC.
    • If the MAC is in the table, forward to that port.
    • If unknown, flood the frame to all ports except the incoming one.

  4. Continuous Learning

    • Over time, the switch learns all active devices and builds a complete table.

5. Switches as the Building Blocks of Networks

Switches provide the foundation for all modern computer networks:

  • They allow us to build the smallest networks — even just two or three devices connected together.
  • As we connect more switches, these small LANs grow into larger campus or enterprise networks.
    • Each switch has a limited number of ports (e.g., 8, 24, or 48).
    • To connect more devices than one switch can support, you can link switches together using one or more ports.
    • This interconnection allows devices connected to different switches to still belong to the same LAN.

6. Special Cases and Resilience

Case 1: Unknown Destination

  • If the switch doesn’t know the destination MAC, it floods the frame to all ports.
  • Once the destination replies, the switch learns the correct port.

Case 2: Table Aging

  • To keep the table accurate, switches use an aging timer.
  • If a MAC address is not seen for a certain period (e.g., 300 seconds), the entry is removed.

Case 3: Power Outage and Recovery

  • Switches usually store the MAC address table in RAM (volatile memory).
  • If power is lost, the table is erased.
  • Upon reboot, the switch starts with an empty table.
  • The learning process begins again automatically as soon as traffic flows.
  • Within seconds or minutes, the switch rebuilds its MAC address table.

Case 4: Port Changes

  • If a device moves to a different port, the switch updates the table automatically when it sees a frame with the same MAC on the new port.

7. Special Case: When Two Nodes Use the Same MAC Address

Normally, each device on a LAN has a unique MAC address. But sometimes:

  • Accidentally (misconfiguration, cloning of virtual machines), or
  • Intentionally (an attacker performing MAC spoofing)

two nodes may use the same MAC address.

How the Switch Reacts

  1. Table Update Behavior

    • A switch associates a MAC address with the last port it was seen on.
    • If Device A (Port 1) and Device B (Port 2) both claim the same MAC address:
      • When a frame arrives from Port 1, the switch updates its table: MAC X → Port 1.
      • When a frame later arrives from Port 2 with the same MAC X, the switch updates: MAC X → Port 2.
    • This causes the entry to flap back and forth between ports.

  2. Impact

    • Frames destined for that MAC will be sent only to the most recently learned port.
    • The other device with the same MAC will not receive frames intended for it.
    • In practice, this results in connectivity issues and unstable communication.

  3. Security Risks

    • Attackers can exploit this to hijack traffic: by spoofing a victim’s MAC, the switch will forward frames to the attacker’s port instead.
    • This is a type of Man-in-the-Middle (MITM) attack.

  4. How Switches and Networks Defend

    • Port Security (Cisco, HP, etc.): Admins can configure switches to allow only specific MAC addresses on a port.
    • Sticky MAC: Switch ``remembers'' which MACs belong to which ports and blocks changes.
    • Alerts/Logs: Many switches log ``MAC flapping'' or security violations.

Ethernet and the MAC Layer (i.e., examine packets at the MAC address level)

1. Ethernet Frame/Packet Structure

An Ethernet frame has three main parts:

+-------------------+-------------------+-----------+-------------------+----------+
| Destination MAC   | Source MAC        | EtherType | Payload (46–1500) |   CRC    |
| (6 bytes)         | (6 bytes)         | (2 bytes) |                   | (4 bytes)|
+-------------------+-------------------+-----------+-------------------+----------+
  • Destination MAC (6 bytes) → where the frame is going.
  • Source MAC (6 bytes) → who sent the frame.
  • EtherType (2 bytes) → what type of payload follows (e.g., IPv4, ARP, IPv6).
  • Payload (46–1500 bytes) → the actual data being carried.
  • CRC (4 bytes) → Cyclic Redundancy Check, used for error detection.

2. Example of an Ethernet Frame

Suppose Device A sends an IPv4 packet to Device B:

  • Destination MAC: 00:11:22:33:44:55
  • Source MAC: AA:BB:CC:DD:EE:FF
  • EtherType: 0x0800 (IPv4)
  • Payload: IP packet
  • CRC: calculated automatically by the NIC

3. Using Wireshark to Parse Ethernet Frames

You can use the following Python code to generate Ethernet frames/packets. Please note that EtherType field is not specified.

#!/usr/bin/env python3
from scapy.all import Ether, sendp, get_if_hwaddr
import sys

def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <destination-mac> [iface] [count]")
        sys.exit(1)

    dst_mac = sys.argv[1]
    iface = sys.argv[2] if len(sys.argv) > 2 else "eth0"
    count = int(sys.argv[3]) if len(sys.argv) > 3 else 5

    # Get the source MAC of the interface
    try:
        src_mac = get_if_hwaddr(iface)
    except Exception as e:
        print(f"[!] Failed to get MAC for interface '{iface}': {e}")
        sys.exit(1)

    # Generate payloads: "AAAA", "BBBB", "CCCC", etc.
    payloads = [chr(65 + i) * 4 for i in range(count)]  # 65 = 'A'

    print(f"[+] Using iface={iface}, src={src_mac}, dst={dst_mac}, count={count}")
    for idx, payload in enumerate(payloads, start=1):
        pkt = Ether(src=src_mac, dst=dst_mac) / payload
        print(f"[+] Sending packet {idx}: src={src_mac}, dst={dst_mac}, payload={payload}")
        sendp(pkt, iface=iface, verbose=False)

    print("[+] Done.")

if __name__ == "__main__":
    main()

Now, if you use WireShark to capture packets, you will see these packets transferred via the links. Wireshark shows Ethernet headers clearly:

  1. Open Wireshark and start a capture.
  2. Select a packet and expand the “Ethernet II” section.
  3. You will see:
    • Destination MAC Address
    • Source MAC Address
    • Type (EtherType)

Example (Wireshark output):

Ethernet II
    Destination: ff:ff:ff:ff:ff:ff (Broadcast)
    Source: 14:ac:60:2e:2a:75
    Type: ??

6. Summary

  • Ethernet uses MAC addresses for delivery inside a LAN.
  • Each frame includes destination, source, type, payload, and CRC.
  • The EtherType field identifies the payload protocol (e.g., IPv4, ARP, IPv6).
  • Wireshark is widely used to inspect and understand these headers.
