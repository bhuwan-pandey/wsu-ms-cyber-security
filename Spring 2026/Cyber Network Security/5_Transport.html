Transport Layer Protocols: UDP and TCP

By Dr. Junjie Zhang

1. From IP to Transport Layer

Recall from the previous lecture:

  • The IP protocol delivers packets from one host to another host (identified by IP addresses).
  • However, hosts run multiple applications simultaneously (e.g., web browser, email, SSH).

How does the network know which application inside the host should receive the packet?

This is why we need ports.

  • IP address → identifies the host.
  • Port number → identifies the application (process) inside the host.

Together, (IP, Port) defines a communication endpoint.

2. UDP: User Datagram Protocol

UDP is the simplest transport protocol.
It simply adds ports on top of IP packets.

UDP Header (8 bytes)

Field Size (bits) Description
Source Port 16 Sender application port
Destination Port 16 Receiver application port
Length 16 Total length (header + data)
Checksum 16 Error detection

Characteristics of UDP

  • Connectionless: no setup before sending.
  • Unreliable: no retransmission, no acknowledgment.
  • No ordering: packets may arrive out of order.
  • Lightweight: very small header, fast.

Example Uses

  • DNS queries (port 53)
  • Video/audio streaming
  • Online games

3. Limitations of IP and UDP

  • IP provides only host-to-host delivery.
  • UDP adds port-to-port delivery, but…
    • Still unreliable (packets may be lost).
    • No guarantee of order.
    • No congestion or flow control.

What if we want to send a file and ensure every byte arrives in order?

This motivates the design of TCP.

4. TCP: Transmission Control Protocol

TCP solves the reliability problem of IP/UDP by adding mechanisms for:

  • Connection establishment (handshake).
  • Reliable delivery (ACKs, retransmissions).
  • In-order delivery (sequence numbers).
  • Flow control (window size).
  • Congestion control (adapts to network load).

TCP Header (minimum 20 bytes)

Field Size (bits) Description
Source Port 16 Application port
Destination Port 16 Application port
Sequence Number 32 Position of first byte in this segment
Acknowledgment # 32 Next byte expected
Flags (SYN, ACK, FIN, etc.) 9 Connection control
Window Size 16 Flow control
Checksum 16 Error detection

TCP Connection Establishment: 3-Way Handshake

sequenceDiagram
    participant C as Client
    participant S as Server

    C->>S: SYN (Seq = x)
    S->>C: SYN-ACK (Seq = y, Ack = x+1)
    C->>S: ACK (Ack = y+1)
  • Client requests a connection (SYN).
  • Server accepts (SYN-ACK).
  • Client confirms (ACK).
  • Connection established.

TCP Reliability

  1. Sender transmits data with a sequence number.
  2. Receiver acknowledges with an ACK number.
  3. If lost, sender retransmits.

TCP also ensures ordering — data arrives to the application in the correct sequence.

5. Comparing UDP and TCP

Feature UDP (Simple) TCP (Reliable)
Based on IP Adds only ports Adds ports + reliability
Connection None (stateless) 3-way handshake (stateful)
Reliability None Guaranteed (ACK + retransmit)
Ordering None In-order delivery
Speed Fast, minimal overhead Slower due to overhead
Use Cases DNS, streaming, gaming Web, email, file transfer

🔎 Checking Ports in Linux

To see which ports are associated with which processes/applications, we can use:

netstat (older, but widely used)

netstat -tulnp
  • -t → TCP
  • -u → UDP
  • -l → Listening ports
  • -n → Show numbers (not names)
  • -p → Show process using the port

Example Output:

Proto Recv-Q Send-Q Local Address    Foreign Address   State   PID/Program name
tcp        0      0 0.0.0.0:22       0.0.0.0:*         LISTEN  1234/sshd
udp        0      0 127.0.0.1:53     0.0.0.0:*                 5678/dnsmasq

ss (modern replacement for netstat)

ss -tulnp

lsof (list open files, including network sockets)

sudo lsof -i -P -n

These commands let you map ports → processes, which makes the abstract concept of “ports identify applications” concrete on a real system.

6. Summary

  • IP: host-to-host delivery.
  • UDP: adds ports → process-to-process delivery, but still unreliable.
  • TCP: builds reliability on top of IP/UDP with handshake, ACKs, sequence numbers, flow & congestion control.
  • Choice depends on the application:
    • UDP for speed (streaming, gaming).
    • TCP for reliability (web, email, file transfer).
