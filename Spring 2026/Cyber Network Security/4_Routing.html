IP Protocols and Routers

By Dr. Junjie Zhang

1. Internet Protocol (IP) Header

The Internet Protocol (IP) is the foundation of packet-switched networks. An IP header contains essential information that allows packets to travel from a source host to a destination host across multiple networks.

IPv4 Header Structure

Field Size (bits) Description
Version 4 IPv4 (4) or IPv6 (6).
IHL (Header Length) 4 Length of the header in 32-bit words.
Type of Service (ToS) 8 Packet priority / QoS.
Total Length 16 Entire packet length (header + data).
Identification 16 Unique ID for fragmentation.
Flags 3 Control fragmentation.
Fragment Offset 13 Position of fragment in original datagram.
Time To Live (TTL) 8 Limits packet lifetime. Decremented by each router.
Protocol 8 Encapsulated protocol (TCP=6, UDP=17, ICMP=1).
Header Checksum 16 Error-checking for header.
Source IP Address 32 Sender’s IP address.
Destination IP Address 32 Receiver’s IP address.
Options (optional) variable Rarely used.
Data variable Payload.

2. NIC Configuration and Gateway

Let us first revisit the typical configuration of a Network Interface Card (NIC), as discussed in the section on Local Area Network and Switches. The ifconfig command shows the details of a host’s NIC:

$ ifconfig
wlp0s20f3: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.0.175  netmask 255.255.255.0  broadcast 192.168.0.255
        inet6 fe80::a286:1d8b:6070:5cc4  prefixlen 64  scopeid 0x20<link>
        ether 6c:6a:77:d8:70:5c  txqueuelen 1000  (Ethernet)
        RX packets 202255  bytes 207443658 (207.4 MB)
        RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 80927  bytes 33460286 (33.4 MB)
        TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0

From this output we see:

  • IP address: 192.168.0.175
  • Netmask: 255.255.255.0 → indicates the /24 subnet (192.168.0.0/24).
  • MAC address: 6c:6a:77:d8:70:5c

With just the IP address, netmask, and MAC address, this node can communicate directly with any other device inside the same LAN (i.e., any host in the 192.168.0.0/24 network).

However, to reach a node outside this LAN, for example, a server on another LAN, the host must forward its packets to a gateway. The gateway is typically a router that connects the LAN to other networks.

We can identify the gateway using the ip route show command:

$ ip route show
default via 192.168.0.1 dev wlp0s20f3 proto dhcp metric 600

The keyword default indicates the route taken when the destination is not part of the local network. Here, 192.168.0.1 is the IP address of the gateway. Packets destined for networks outside 192.168.0.0/24 are forwarded to this gateway, which is the router responsible for relaying them toward their final destination.

3. Deciding How to Send Packets

General Rules

  • If the destination is in the same subnet, send the packet directly using the destination’s MAC address.
  • If the destination is in a different subnet, forward the packet to the gateway’s MAC address; the gateway (router) will then relay it toward its destination.

The following Python-like pseudocode illustrates this decision process:

# The Python-like Pseudo Code
def send_ip_packet(src_ip, dst_ip, netmask, gateway_ip, arp_cache):
    """
    src_ip      : Source host's IP
    dst_ip      : Destination host's IP
    netmask     : Subnet mask of the source host
    gateway_ip  : Default gateway IP
    arp_cache   : Mapping of IP -> MAC (from ARP cache)
    """

    # Step 1. Compute network prefix of source and destination
    src_network = src_ip & netmask
    dst_network = dst_ip & netmask

    # Step 2. Check if destination is in the same LAN
    if src_network == dst_network:
        print("[+] Destination is in the same LAN")
        dst_mac = arp_cache.lookup(dst_ip)  # get MAC of destination host
        if dst_mac is None:
            dst_mac = arp_request(dst_ip)   # broadcast ARP request
    else:
        print("[+] Destination is outside LAN, forward to gateway")
        dst_mac = arp_cache.lookup(gateway_ip)  # MAC of gateway
        if dst_mac is None:
            dst_mac = arp_request(gateway_ip)   # ARP request for gateway

    # Step 3. Build Ethernet frame
    ether_frame = Ether(
        src_mac = arp_cache.lookup(src_ip),  # my MAC
        dst_mac = dst_mac
    ) / IP(src=src_ip, dst=dst_ip) / payload

    # Step 4. Send frame
    send_frame(ether_frame)

4. Introduction to Routing and Routers

Now, this packet arrives at one of the router’s interfaces. What does the router do next?

The router consults its routing table to determine how to forward the packet. The routing table can be thought of as a set of rules or entries, each indicating how to reach a particular destination network. Each entry typically contains:

  • Destination network: The network prefix to match (e.g., 10.0.0.0/24).
  • Next hop IP: The IP address of the next router (if the destination is not directly connected).
  • Interface: The local router interface through which the packet should be forwarded.
  • Flags/Notes: For example, whether the route is directly connected.

For the example network presented above, its routing table might look like this:

Destination Network Next Hop IP Outgoing Interface Notes
192.168.1.0/24 — eth0 Directly connected
10.0.0.0/16 — eth1 Directly connected

Both LANs are directly connected to this router.

How the router decides:

  1. The router checks the destination IP in the incoming packet.
  2. It searches its routing table for the longest prefix match with that IP.
  3. It then forwards the packet out through the corresponding interface, updating the Ethernet header (new source/destination MACs).

6. Practical Tools and Issues

Traceroute

TTL (Time To Live) is an 8-bit field in the IP header. Its purpose is to limit the lifetime of a packet so it doesn’t circulate endlessly in the network due to routing loops or misconfigurations.

How TTL Works

  1. When a host creates an IP packet, it sets an initial TTL value (commonly 64, 128, or 255 depending on the operating system).
  2. Each time the packet passes through a router (hop), the router decrements TTL by 1.
  3. If TTL reaches 0, the packet is discarded, and the router usually sends back an ICMP Time Exceeded message to the sender.

How Traceroute Works

  1. Send a packet with TTL = 1

    • The first router decrements TTL to 0 and discards the packet.
    • It replies with an ICMP Time Exceeded message.
    • Traceroute records this router’s address as Hop 1.

  2. Send a packet with TTL = 2

    • The first router decrements TTL to 1 and forwards the packet.
    • The second router decrements TTL to 0 and discards it.
    • It replies with an ICMP Time Exceeded message.
    • Traceroute records this router’s address as Hop 2.

  3. Increment TTL step by step

    • Traceroute repeats the process, gradually increasing TTL values.
    • Each time, the packet travels one hop further before expiring.
    • Each responding router reveals its IP address along the path.

  4. When the packet finally reaches the destination

    • Instead of a Time Exceeded message, the destination typically replies with an ICMP Port Unreachable (for UDP probes) or an Echo Reply (for ICMP probes).
    • This marks the end of the path.

Why Traceroute is Useful

  • Path Discovery: Shows all routers between source and destination.
  • Troubleshooting: Helps identify where delays, packet loss, or failures occur.
  • Network Analysis: Reveals asymmetric routes and routing policies.

IP Spoofing

Routers are designed with efficiency in mind. When a packet arrives, the router primarily examines the destination IP address in the packet’s header to decide where it should be forwarded. This design choice allows routers to process packets at very high speeds, where they simply look up the destination in the routing table and forward the packet accordingly. Importantly, routers typically do not verify the legitimacy of the source IP address in the packet.

This design limitation opens the door to a technique known as IP spoofing. In IP spoofing, an attacker forges (or “spoofs”) the source IP address in the packet header. Since routers only check the destination IP, spoofed packets are forwarded through the network just like legitimate traffic.

Implications of IP spoofing include:

  • Bypassing filters: Some security systems allow or block traffic based on source IP. Spoofing can be used to evade such controls.
  • Reflection and amplification attacks: Attackers can send requests with a spoofed source IP (victim’s address) to third-party servers. Those servers reply to the victim, overwhelming it with traffic. This is a common strategy in Distributed Denial of Service (DDoS) attacks.
  • Obfuscation: Attackers may spoof IPs to hide their true origin and complicate tracing efforts.

Defenses against IP spoofing:

  • Ingress filtering (RFC 2827): ISPs can block packets with source IPs that do not match the expected range for the customer’s network.
  • Egress filtering: Organizations can block spoofed packets from leaving their networks.

Unfortunately, they are partially deployed, but lack of universal adoption leaves the Internet vulnerable.

In summary, IP spoofing exploits the fact that routers trust the destination IP for forwarding and do not validate source IPs. While simple, it remains a powerful tool for attackers in a range of network attacks.
