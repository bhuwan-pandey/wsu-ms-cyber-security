Address Resolution Protocol (ARP)

By Dr. Junjie Zhang

1. What is ARP?

The Address Resolution Protocol (ARP) is a network protocol used to map a device’s IP address (logical address) to its MAC address (hardware address) within a Local Area Network (LAN).

Since communication using switches requires MAC addresses, ARP acts as the bridge between IP and MAC.

2. Why Do We Need ARP?

It is worthy noting two nodes inside the same LAN can communicate with each other using only MAC addresses. See the script used in the previous section.

But why do nodes/devices usually use IP address of the host they want to communicate with?

  • An Example: My computer knows the IP address of the printer, but we may have a new printer connected to the LAN using the same IP address but it has a different MAC address.

However, since the switch delivers frames using MAC addresses, we will need a protocol to resolve IP → MAC.

3. How ARP Works

Step-by-step Process:

  1. Device A wants to send data to Device B using B’s IP address.
  2. Device A checks its ARP cache to see if it already knows B’s MAC address.
    1. The ARP cache is a table to map an IP into a MAC address.
  3. If not found, Device A sends out an ARP Request:
    • “Who has IP 192.168.1.20? Tell 192.168.1.10.”
    • This request has
      • A's MAC address as the source MAC address.
      • FF:FF:FF:FF:FF:FF as the destination MAC address.
  4. The switch receives this ARP request, finds out the destination MAC address is FF:FF:FF:FF:FF:FF, and flood it to all active ports except the incoming one.
  5. All active nodes connected to the switch, including Device B, receive this ARP request.
  6. Device B responds with an ARP Reply:
    • “I am 192.168.1.20, and my MAC is BB:BB:BB:BB:BB:BB.”
  7. The switch receives this ARP reply, and forwards it to the port that connects with A.
  8. Device A receives this ARP reply, and updates its ARP cache with the new mapping (192.168.1.20 -> BB:BB:BB:BB:BB:BB) and can now send frames to Device B.

ARP Request/Reply Sequence:

sequenceDiagram
    participant A as Device A (192.168.1.10)
    participant B as Device B (192.168.1.20)
    participant S as Switch

    A->>S: 1. Broadcast ARP Request (Who has 192.168.1.20?)
    S->>B: 2. Forwards broadcast
    B->>S: 3. ARP Reply (MAC: BB:BB:BB:BB:BB:BB)
    S->>A: 4. Forwards reply
    A->>B: 5. Sends data frame using B's MAC
  • Step 1 - 4: ARP Protocol
  • Step 5: Communication

Questions to Consider

  1. Does the switch directly provide Device B’s MAC address to Device A?

    • Hint: No. The switch never tells one device the MAC of another. Instead, it only forwards the ARP request and ARP reply frames. Device A learns Device B’s MAC from Device B’s ARP reply, not from the switch.

  2. If the switch has just rebooted and its MAC–port table is empty, will it learn the MAC–port mappings from the ARP request and the ARP reply?

    • Hint: Yes. When the switch receives the ARP request, it records the source MAC of Device A and associates it with the incoming port. When Device B replies, the switch records Device B’s MAC and its port. Over time, the table fills up automatically as frames are exchanged.

This is a python script on a node to generate an ARP request and parse the response (if available). For observing the switch's behavior, you will need to capture packets coming out from the switch.

#!/usr/bin/env python3
from scapy.all import ARP, Ether, srp, get_if_hwaddr, conf
import sys

def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <target-ip> [iface]")
        sys.exit(1)

    target_ip = sys.argv[1]
    iface = sys.argv[2] if len(sys.argv) > 2 else conf.iface  # default Scapy iface

    # Get the source MAC address of the interface
    try:
        src_mac = get_if_hwaddr(iface)
    except Exception as e:
        print(f"[!] Could not get MAC address for interface '{iface}': {e}")
        sys.exit(1)

    # Build an Ethernet frame with the proper source and broadcast destination
    ether = Ether(src=src_mac, dst="ff:ff:ff:ff:ff:ff")
    # ARP request: who-has target_ip? tell <src_mac owner>
    arp = ARP(pdst=target_ip)

    packet = ether / arp

    print(f"[+] Using iface={iface}, src_mac={src_mac}")
    print(f"[+] Sending ARP request for {target_ip} ...")

    answered, unanswered = srp(packet, timeout=2, iface=iface, verbose=False)

    for sent, received in answered:
        print(f"[+] {target_ip} is at {received.hwsrc}")

    if not answered:
        print(f"[-] No response for {target_ip}")

if __name__ == "__main__":
    main()

:gear: Now, you can capture the ARP request and the ARP response using WireShark.

4. ARP Cache

When a device uses ARP (Address Resolution Protocol) to find the MAC address of another host in the LAN, it does not want to repeat the broadcast request every time it needs to communicate. Instead, it stores the result in a local table called the ARP cache. For example:

  • Device A: IP 192.168.1.10, MAC AA:AA:AA:AA:AA:AA
  • Device B: IP 192.168.1.20, MAC BB:BB:BB:BB:BB:BB

You can check the ARP cache on your computer easily using:

On Linux

arp -n

On Windows:

arp -a

On GNS3 VPC:

arp

All future communication is sent directly without another ARP broadcast (until cache expires). ARP cache expiration varies by OS.

  • Linux: ~30–60 seconds (refresh on use).
  • Windows: ~2 minutes → extended to 10 minutes if active.
  • macOS/BSD: ~20 minutes.
  • Static entries: never expire.

6. Security Implications

  • ARP Scanning: Attackers can identify active IP addresses in the LAN.
  • ARP Spoofing/Poisoning: Attackers can send fake ARP replies to hijack traffic. This is a common network attack.

We will discuss ARP Spoofing later. For this section, we will focus on ARP scanning.

You can find a SCAPY script below, that scans all IP addresses in the LAN of the selected interface. Specifically, the script attempts to automatically determine your active interface, its connected IPv4 network (CIDR), and then performs an ARP reqeust for each IP address.

#!/usr/bin/env python3
from scapy.all import ARP, Ether, srp, get_if_hwaddr, conf
import ipaddress
import sys

def main():
    if len(sys.argv) < 2:
        print(f"Usage: {sys.argv[0]} <target-ip-or-cidr> [iface]")
        print(f"Examples:")
        print(f"  sudo {sys.argv[0]} 192.168.10.23 eth0")
        print(f"  sudo {sys.argv[0]} 192.168.10.0/24 eth0")
        sys.exit(1)

    target = sys.argv[1]  # can be single IP or CIDR
    iface = sys.argv[2] if len(sys.argv) > 2 else conf.iface  # default Scapy iface

    # Get the source MAC address of the interface
    try:
        src_mac = get_if_hwaddr(iface)
    except Exception as e:
        print(f"[!] Could not get MAC address for interface '{iface}': {e}")
        sys.exit(1)

    print(f"[+] Using iface={iface}, src_mac={src_mac}")

    # Build Ethernet broadcast template
    ether = Ether(src=src_mac, dst="ff:ff:ff:ff:ff:ff")

    packets = []
    # Try to interpret target as a CIDR; if that fails, treat as single IP
    try:
        net = ipaddress.ip_network(target, strict=False)
        # Enumerate each usable host in the CIDR
        for ip in net.hosts():
            packets.append(ether / ARP(pdst=str(ip)))
        pretty_target = f"{net.with_prefixlen}"
    except ValueError:
        # Single IP target
        packets.append(ether / ARP(pdst=target))
        pretty_target = target

    print(f"[+] Sending ARP request(s) for {pretty_target} ...")

    answered, unanswered = srp(packets, timeout=2, iface=iface, verbose=False)

    # If CIDR: print a table of all responders; if single IP: keep original print
    results = []
    for sent, received in answered:
        results.append((received.psrc, received.hwsrc))

    if len(results) == 0:
        print(f"[-] No response for {pretty_target}")
        return

    # If only one probe (single IP), keep the simple line
    if len(packets) == 1:
        ip, mac = results[0]
        print(f"[+] {ip} is at {mac}")
    else:
        # Table for multiple results
        width_ip = max(len(ip) for ip, _ in results)
        print("\nIP".ljust(width_ip), "MAC Address")
        print("-" * width_ip, "-------------------")
        for ip, mac in sorted(results, key=lambda x: tuple(int(o) for o in x[0].split("."))):
            print(ip.ljust(width_ip), mac)

if __name__ == "__main__":
    main()

7. Summary

  • ARP maps IP addresses to MAC addresses within a LAN.
  • ARP is essential for communication in Ethernet-based LANs.
  • Tools like arp -a allow us to see mappings in action.
  • Security risks exist (e.g., ARP scanning and ARP spoofing), so monitoring is important.
