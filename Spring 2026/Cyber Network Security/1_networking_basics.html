Network Interface Controller and Network Addresses

By Dr. Junjie Zhang

Network Interface Controller (NIC)

A Network Interface Controller (NIC) is a hardware component that allows a computer to connect to a network. A NIC is also referred to as

  • a network interface card,
  • network adapter,
  • LAN adapter, or
  • physical network interface.

It provides the physical and logical interface between a computer (or other device) and an Ethernet network.

  • Each NIC is uniquely identified by a MAC (Media Access Control) address, which is permanently assigned to it by the manufacturer.
  • In addition, each ethernet NIC can be additionally configured with an IP (Internet Protocol) address, enabling logical communication across different networks.

Examples:

  • An Ethernet NIC is a type of network interface controller designed specifically for wired Ethernet connections (e.g.,., the Internet).
  • A wireless NIC is a network interface controller which connects to a wireless network, such as Wi-Fi, Bluetooth, or LTE (4G) or 5G rather than a wired network, such as an Ethernet network.

Network Addresses -- MAC Addresses and IP Addresses

In a network, multiple devices (computers, phones, printers, servers) are interconnected. To ensure that information reaches the correct destination, we need addresses. There are two types of addresses.

  • Media Access Control (MAC) address

    • Definition: A Media Access Control (MAC) address is a unique hardware address assigned to a device’s network interface card (NIC).
    • Format: 48 bits.
    • Scope: Works within a single local network (LAN).

  • Internet Protocol (IP) address

    • Definition: An Internet Protocol (IP) address is a logical identifier assigned to a device to enable communication across networks.
    • Versions:
      • IPv4: 32-bit
      • IPv6: 128-bit
    • Scope: Works across different networks (LANs, WANs, Internet).
$ ifconfig
eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 172.21.4.154  netmask 255.255.240.0  broadcast 172.21.15.255
        inet6 fe80::215:5dff:fefb:b256  prefixlen 64  scopeid 0x20<link>

        RX packets 517  bytes 61798 (61.7 KB)
        RX errors 0  dropped 0  overruns 0  frame 0

The MAC address is 00:15:5d:fb:b2:56, and the IPv4 address is 172.21.4.154.

Q: But you told me the IP address has 32 bits.

MAC Address: 48-bit Sequence → Colon-Separated Hexadecimal

A MAC address is fundamentally a 48-bit binary sequence.
For readability, this sequence is split into six groups of 8 bits (octets). Each octet is then converted into a two-digit hexadecimal number and separated by colons (:).

  1. Start with a 48-bit sequence:
00000000 00011010 00101011 00111100 01001101 01011110
  1. Split into 6 octets (8 bits each):
00000000 : 00011010 : 00101011 : 00111100 : 01001101 : 01011110
  1. Convert each octet to hexadecimal:
  • 00000000 → 00
  • 00011010 → 1A
  • 00101011 → 2B
  • 00111100 → 3C
  • 01001101 → 4D
  • 01011110 → 5E
  1. Combine them with colons:
00:1A:2B:3C:4D:5E

IPv4: 32-bit Sequence → Dotted Decimal Notation

An IPv4 address is fundamentally a 32-bit binary sequence.
For readability, this sequence is split into four groups of 8 bits (octets). Each octet is then converted into a decimal number (0–255) and separated by dots (.).

  1. Start with a 32-bit sequence:
11000000101010000000000100001010
  1. Split into 4 octets (8 bits each):
11000000 . 10101000 . 00000001 . 00001010
  1. Convert each octet to decimal:
  • 11000000 → 192
  • 10101000 → 168
  • 00000001 → 1
  • 00001010 → 10
  1. Combine them with dots:
192.168.1.10

You can also convert an IPv4 Address into a 32-bit sequence.

# convert an IP address into 32 bits.
import ipaddress
def ipv4_to_bits_stdlib(ip: str) -> str:
    addr = ipaddress.IPv4Address(ip)  # validates format and range
    return format(int(addr), "032b")

# Examples:
print(ipv4_to_bits_stdlib("192.168.1.10"))
print(ipv4_to_bits_stdlib("8.8.8.8"))

MAC Address and Manufacturers

A MAC (Media Access Control) address is not just a random identifier. The first 24 bits (the first three octets), known as the Organizationally Unique Identifier (OUI), are assigned by the IEEE to hardware manufacturers. This ensures that each device produced by a vendor has a unique address.

  • OUI (first 3 bytes) → identifies the manufacturer.
  • Device-specific portion (last 3 bytes) → uniquely identifies a specific network interface card (NIC) made by that manufacturer.

This structure means that by examining a MAC address, you can often determine the vendor of the device.

Examples

  • 00:1A:2B:xx:xx:xx → Cisco Systems, Inc.
  • 3C:5A:B4:xx:xx:xx → Google, Inc.
  • AC:DE:48:xx:xx:xx → Intel Corporation
  • F0:27:65:xx:xx:xx → Apple, Inc.
  • B8:27:EB:xx:xx:xx → Raspberry Pi Foundation

(Here xx:xx:xx represents the device-specific part assigned by the manufacturer.)

Why This Matters

  • Network Management: IT administrators can quickly identify which vendor a device belongs to.
  • Troubleshooting: Helps in locating faulty or unauthorized devices.
  • Security: Useful in access control lists (ACLs) and monitoring rogue devices.

IP Addresses and Organizations

An IP (Internet Protocol) address is not just a random number. Behind every IP address is an organization or Internet Service Provider (ISP) that has been allocated responsibility for managing it. Much like how the first part of a MAC address (the OUI) identifies the manufacturer, an IP address belongs to a block assigned by a Regional Internet Registry (RIR) to a specific organization. This ensures that each IP block on the Internet is uniquely managed and traceable.

  1. Global Allocation
    • The Internet Assigned Numbers Authority (IANA) oversees the global pool of IP addresses.
    • Large blocks are delegated to Regional Internet Registries (RIRs):
      • ARIN – American Registry for Internet Numbers (North America)
      • RIPE NCC – Europe, Middle East, parts of Central Asia
      • APNIC – Asia Pacific
      • LACNIC – Latin America and Caribbean
      • AFRINIC – Africa
  2. Assignment to Organizations
    • Each RIR further allocates smaller IP ranges to ISPs, universities, companies, and government agencies.
    • These allocations ensure uniqueness and accountability for every address on the Internet.
  3. Looking Up the Organization
    • Tools such as the whois command can query these databases to find:
      • Organization name
      • Network range (CIDR block)
      • Country and region
      • Administrative and technical contact details

Examples of IP-to-Organization Mapping

  • IP address 8.8.8.8 → Google LLC (Google Public DNS)
  • IP address 1.1.1.1 → Cloudflare, Inc. (Cloudflare Public DNS)
  • Network block 128.143.0.0/16 → University of Virginia

Practical Example: Using whois

Suppose we want to know the organization behind Google’s public DNS IP address 8.8.8.8.

Command:

whois 8.8.8.8

Sample Output (simplified):

NetRange:       8.8.8.0 - 8.8.8.255
CIDR:           8.8.8.0/24
NetName:        LVLT-GOGL-8-8-8
Organization:   Google LLC (GOGL)
RegDate:        2014-03-14
Updated:        2014-03-14
Country:        US

Interpretation:

  • The block 8.8.8.0/24 belongs to Google LLC.
  • The address is registered in the United States.
  • The entry provides both technical and administrative information, ensuring transparency.

Why This Matters

  • Network Management: Administrators can trace where network traffic originates.
  • Security: Helps detect suspicious IP addresses and link them back to real organizations.
  • Research: Provides insights into global Internet infrastructure and address usage.
